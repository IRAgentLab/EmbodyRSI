## 4. CLAW 类框架的具身扩展

- **OpenClaw**：确认是一个正在快速扩张的通用 Agent Harness/技能生态（2026 年 8–9 月出现大量围绕它的安全与治理论文，如 *Loopjacking*、*HazardAuditor*、*After the Party: Growth, Governance and Security Scanning in the OpenClaw Agent Skill Ecosystem* 等），EvoMaster 明确构建在其上（作者列表出现 "OpenClaw EvoMaster" 实体）。除 EvoMaster 外，未检索到专门"把 OpenClaw 扩展到具身/机器人领域"的论文；检索到一篇同期但**团队不同、方向也不同**的 *Harness Robotic OS: A Unified Embodied-Agent Runtime for Closed-Loop Quadruped Inspection*（[arXiv 2609.11225](https://arxiv.org/abs/2609.11225)，2026-09-10），它是四足巡检机器人的部署期运行时（多模态感知+人机交互+企业响应闭环），不是训练期研发 Agent，也与上海交大团队无作者交叠，只是术语上都用了 "Harness"，需要待核实是否与 OpenClaw 生态有实质关联。
- **Clawe**：未检索到与此名称匹配的具身相关论文或框架，标记为**待核实**（可能是尚未公开发表的内部代号，或检索关键词有误）。

## 5. RoboCoach 及其后续工作在"数据生产管线 / 仿真环境与资产 / 观测模态"三层上的覆盖程度

这是本次检索最重要的结论，直接回答我们研究定位的问题：**Agent 读 VLA 执行记录诊断能力缺口后，是否已经有人真正打通"改数据生产、改仿真环境资产、改观测"这三层，而不只是改训练代码/超参？**

答案是：**三层都还没有被真正打通，最多是碎片化、割裂在闭环之外的能力，这正是空白。**

- **训练数据生产管线**：RoboCoach 本身明确只改"训练代码、奖励、损失、架构、超参、数据处理代码"，不生成新数据、不采集新演示。它的同组前序 EmboMatrix（2510.12072）确实有"多智能体数据引擎做任务/场景生成"，但那是一条独立的、离线的、预先搭好的基础设施，不是被诊断驱动、按需为某个具体策略的能力缺口去生产新数据。RISE（2602.11075）用世界模型"想象"出训练用的合成 rollout，但决策者是 RL 算法而非诊断式 LLM Agent。Cortex（2607.05377）有自动标注视频+生成仿真数据的管线，但是人工预设规则，不是 Agent 按诊断结果动态决定要采集什么样的数据。**结论：数据生产层有零星的技术拼图，但"诊断驱动"的闭环里还没人把它接进去。**
- **仿真环境与资产**：同样只有 EmboMatrix 触及（场景/任务生成、分布式仿真），且是团队自己另一条产品线，与 RoboCoach 的诊断循环没有代码或方法上的耦合关系（两篇论文互不引用彼此的循环机制）。ENPIRE（2606.19980）的 Environment 模块做的是真实场景的"复位与校验"，不是生成或编辑仿真资产。**结论：没有发现任何论文让"诊断具身能力缺口的 Agent"直接去编辑仿真资产、增删物体、改物理参数或重新生成场景。**
- **观测模态**：本次检索（包括 RoboCoach 全文既有认知、EvoMaster、EmboMatrix、ENPIRE、VLAs-as-Tools、NavMCP、RISE、RDA、Cortex 等全部候选论文的摘要）**没有发现任何一篇让 Agent 在诊断出"感知/遮挡/视角"类能力缺口后，主动决定增加相机视角、切换到深度/触觉输入、或更换观测编码器**。RoboCoach 自己工作在 ManiSkill3/RoboTwin2.0/Robomimic/MetaWorld 固定的观测协议下；其余同期工作也都假定观测模态固定。**结论：这一层目前是完全的空白，待核实是否有更晚近（9 月之后）或未公开检索到的工作触及。**

综上，"训练代码与超参"这一层已经从 RoboCoach 走向了跨领域通用框架（EvoMaster）；"数据生产"和"仿真环境资产"这两层各自都有独立的、非 Agent 诊断驱动的技术积累（EmboMatrix、Cortex），"环境复位/校验"在真实世界侧有 ENPIRE 这一步；但**没有一篇论文把"读执行记录诊断能力缺口"和"改数据生产/改仿真资产/改观测模态"这三件事用同一个闭环连起来**——这正好是当前文献里尚未被占据的位置。
