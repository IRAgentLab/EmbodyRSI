## E. 仿真基准本身的缺陷与修复（资产 bug、判据漏洞、reward hacking、benchmark contamination）

这是本次调研中**收获最少**的方向，如实报告：

- **专门审计/修复具身仿真基准资产 bug 的 2026 论文**：未检索到。多组合关键词（"asset"+"simulation"+"robot learning"+"repair"、"benchmark contamination"+"robot"）均返回 0 条。
- **判据漏洞/终止条件 bug**：未检索到（"termination condition"+"robot"+"simulation"+"success"+"bug" 返回 0 条；"evaluation criteria"+"exploit"+"robot"+"simulation" 返回 0 条）。
- **Reward hacking 相关**，检索到的均为**非具身**领域的通用 AI 工作，仅作为方法论参照：
  - *Controllable Sim Agents with Behavior Latents*（CNeVA，交通仿真，2026-07，[2607.02496](https://arxiv.org/abs/2607.02496v1)）——提出"操控性指标必须配合物理合理性护栏，否则会有 reward-hacking 混淆"，思路可借鉴到具身评测设计。
  - *OdysSim*（人类行为仿真基础模型，2026-06，[2606.14199](https://arxiv.org/abs/2606.14199v2)）——观察到"LLM-as-judge RL 会诱发 reward hacking 模式"。
  - *SpecBench*（长程编码 agent 的 reward hacking 度量，2026-05，[2605.21384](https://arxiv.org/abs/2605.21384v2)）——量化可见测试与隐藏测试的表现差，方法论可迁移到"具身评测判据是否被利用"。
- **测试集污染/泄露**：检索"test set leakage / data contamination"+"robot"+"benchmark"，返回的全部是 LLM/文本领域工作（如 *Contamination Inflates Scores but Rarely Reorders LLM Leaderboards*，2026-07，[2609.02899](https://arxiv.org/abs/2609.02899v1)），**没有一篇专门讨论具身/机器人基准的污染或"针对测试失败造数据"的泄露问题**。
- **相邻但不完全对口**的两篇：
  - *UAMTERS*（DL 机器人软件的不确定性感知变异测试，2026-02，[2602.20334](https://arxiv.org/abs/2602.20334v1)）——用变异算子向机器人软件注入随机不确定性做测试有效性评估，是"软件测试"视角而非"仿真资产/物理 bug"视角。
  - *RoboTwin-Phys*（2026-09，[2609.26292](https://arxiv.org/abs/2609.26292v1)）——扩展 RoboTwin，系统性改变 13 种物理属性以测量/提升 WAM 和 VLA 的鲁棒性；这更接近"用扰动测鲁棒性"而非"审计并修复基准自身的资产/判据 bug"。
- 另需提醒：检索到一篇 **AM-Bench: A Modular Simulation Suite and Benchmark for Aerial Manipulation Policy Learning**（CMU Guanya Shi 组，2026-09，[2609.00641](https://arxiv.org/abs/2609.00641v1)），与用户记忆笔记中提到的"AM-Bench 资产 bug 清单"名称相同，建议直接核对是否为同一基准、是否已有人公开报告过资产 bug，避免重复劳动或误判为"我们独有发现"。

**结论**：E 方向在 2026 年几乎是**真空地带**——"具身仿真基准的资产/判据 bug 审计与修复"作为一个独立研究话题，尚未形成公开文献。这既说明我们"发现并系统化修复 AM-Bench 类资产 bug"的工作有较高稀缺性，也说明这个话题可能被大厂/团队当作内部工程细节而非独立论文发表，检索不到不等于没人做，需要保持警惕。

## 2. 与我们三个创新点的逐条对照

### 创新点 1：视频为主证据的失败理解 + 特权视角 + 探针实验
- **"视频为主证据做失败检测/归因"这一部分，2026 年已经相当拥挤**：ProTracer、RAFAIL、FailBench、LabRobFail、Robot Critics that Sweat the Small Stuff、Fail-RAG、KITE、ARMOR、PRM-as-a-Judge 等至少 9 篇工作在做同类事情，其中 KITE 的"视频转标记化证据供 VLM 用"与我们的表征思路几乎一致。**这部分新意已被大量消耗，必须靠差异化取胜，不能作为主要卖点单独立论**。
- **"仿真特权视角辅助 VLM 诊断"（碰撞体、接触力渲染、真值状态）：未检索到任何直接对应工作**。最接近的 ProTracer 用的是真实机器人本体感知信号，不是仿真器特权渲染；这是目前看来**仍然成立、且尚未被抢占的新意点**，应尽快落地形成先发优势。
- **"探针实验"（针对失败假设做主动干预验证）**：具身领域未检索到对应工作；通用 AI4AI 领域有零星苗头（如 *An AI Scientist that Doesn't Drift* 用"证伪 3/4 自己假设"的机制、*One Reflection Is Not Enough / SAGE* 把失败归因当作结构化因果诊断），但都在 ML 实验场景，未迁移到具身失败诊断。**结论：探针实验+特权视角的组合仍是新意，但通用 AI4AI 领域"假设-验证"范式正在快速成熟，留给我们的时间窗口在缩短**。

### 创新点 2：失败驱动的仿真缺陷修复与增强任务/数据/观测设计
- **"失败/物理不可行触发任务或数据修复"已有先例**：FATE（修任务可行性）、Scene2Demo（失败触发动作流程修改）、Self-Evolving Learning w/ Criticality Model（优先失败案例做数据）都在做"观察到问题→自动改进任务/数据"的闭环，**这个大方向的新意也已被部分消耗**。
- **但"VLM 看失败视频判断出这是仿真器本身的资产碰撞体/reset 脚本/专家脚本 bug，而不是策略问题，并针对性修复仿真代码"——检索不到任何一篇工作做到这一步**。现有工作修的都是"任务定义/课程/动作序列"这一层，没有下钻到"仿真器代码本身有 bug"这一层。**这是目前证据最支持"仍是空白"的创新点**，尤其是 E 方向的全面真空（未检索到具身仿真基准资产/判据 bug 审计修复的公开文献）进一步印证了这一判断。
- 风险提示：SimWorld Studio 的"编码 agent 直接写引擎级代码建环境"技术上已经具备"顺手改资产代码"的能力基础，如果该团队或类似团队把落点从"生成新环境"转向"修复已有环境的 bug"，会直接侵入我们的空白区，需要加速抢占。

### 创新点 3：带真值的失败视频基准
- **"构造带真值失败标签的具身基准"这一想法在 2026 年已出现多个独立尝试**：FailBench（判成功/失败可靠性）、LabRobFail（失败中心大规模基准）、When Should a Failing Robot Ask?（**明确人为注入已知失败原因**）、TrapVLA（人为配置失败模式+自动化保真度量化）。**这说明"真值标注失败基准"本身已不再是全新想法，我们不能只靠"有真值"这一点论证创新性**。
- 但这些工作的真值来源和用途都不同于我们：FailBench/LabRobFail 的真值主要是"任务成功与否"或专家标注的失败类别；When Should a Failing Robot Ask 的注入真值服务于"是否该向人求助"的决策研究；TrapVLA 的注入服务于攻击/红队评测。**没有一篇工作把"真值"具体定义为"区分策略失败 vs. 仿真器/资产缺陷导致的伪失败"，也没有一篇把这种真值基准和后续的仿真修复流程串联起来**。这是我们第三个创新点目前仍站得住脚的窄口——但窄口比半年前明显收窄，建议尽快把"仿真缺陷 vs 策略失败"这个标签体系和配套基准做出来并发表，抢占这个具体切口，而不是泛泛主张"我们有真值基准"。

### 总体判断
三个创新点中，"视频为主证据"和"真值失败基准"两个大方向的**外围**已经被 2026 年密集的工作覆盖，我们必须收紧到更具体的差异化主张（仿真特权视角融合、探针实验、策略失败/仿真缺陷区分标签体系）才能维持新意；而"失败驱动的仿真资产/脚本级修复"这一环节，无论是从 B 方向的检索结果还是 E 方向的全面空白来看，仍然是相对最扎实的空白区，建议作为论文/系统的核心卖点优先突破和发表。
