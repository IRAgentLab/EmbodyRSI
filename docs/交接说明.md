# 交接说明

给接手本项目的同学。先读这一页，再按"阅读顺序"读其他文档。

## 一句话

我们想让 Agent 充当具身模型的研发工程师：读模型执行后的记录（视频加数值），推断模型缺什么能力、或者环境本身有什么缺陷，再去改训练数据的生产方式、训练环境、观测与模型结构，形成自动迭代的闭环。我们已经在 AM-Bench 上由人加 AI 手工跑通了一次这个闭环，现在要把它自动化并写成论文。

## 阅读顺序

1. `研究规划.md`：定位、创新点、相关工作、目标实验（网页版 `html/research_plan.html`）。
2. `AMBench迭代记录.md`：70 条真实迭代，包含每次判断用了什么输入、对不对、改了什么、效果如何。这是论文最重要的一手证据，也是诊断基准的真值来源。
3. `仿真修复清单.md`：查实的仿真缺陷与修法。
4. `AMBench实验现状.md`：目前的成绩和进行中的实验。
   `RoboTwin基线复测.md`：主基准 RoboTwin 2.0 上 π₀.₅ 的官方基线与复测步骤。
5. `../vlm_pilot/README.md` 与 `../vlm_pilot/RESULTS.md`：VLM 能否从视频看出失败原因的先导实验。
6. `HPC使用要点.md`：上机前必读，里面每条都是踩过的坑。
7. `surveys/` 与 `literature/`：文献调研。最接近的工作是 RoboCoach（arXiv 2601.21570），先读 `literature/EmboCoach-Bench/精读笔记.md`。

## 建议分工

两个方向相对独立，可以并行：

**方向 A：诊断（Agent 能不能看懂失败）**
- 在 `vlm_pilot` 的基础上，按规划做"证据分级"对比：只给日志与指标、加默认视频、加仿真特权视角（碰撞体、接触力渲染）、再允许探针实验。
- 构建诊断基准：向仿真注入已知缺陷（去碰撞体、错工具点、实心容器、错误摩擦、错误 reset 等），混入真实的策略失败，标注"环境缺陷 / 能力缺口 / 具体根因"。先用 `AMBench迭代记录.md` 里真实发现的缺陷作为第一批真值。
- 注意：检查清单式提示词必须在未见过的缺陷类型上检验，防止为已知案例量身定做。

**方向 B：闭环（Agent 能不能改对研发管线）**
- 复测 RoboTwin 2.0 上的 π₀.₅ 官方基线（联合训练 easy 70.7、hard 46.0，官方 checkpoint 已公开，步骤见 `RoboTwin基线复测.md`），补测 LIBERO-PRO 上的 π₀.₅ 基线。
- 把 `ambench_patches/scripts/` 里的录制、训练、评测、探针脚本整理成 Agent 可调用的工具接口。
- 先在 LIBERO-PRO 上跑通最小闭环，再做"只改训练代码的 Agent"对照（RoboCoach 式，或用 Claude Code / Codex 实现）。

两个方向在"诊断结果驱动编辑"处汇合。

## 几条已经验证过的经验

- 只看评测数字几乎从来不能说明"为什么失败"，迭代记录里 17 次只对 1 次；探针实验（静止对照、单轴运动对照）最可靠。
- 看起来像"夹得不够紧"的问题，要先看夹爪开度：0.002 表示根本没有夹住东西。
- 仿真在任务成功后会自动 reset，调试时必须捕获 `terminated`，否则会把成功看成失败。
- 环境修复会改变基准本身。报告成绩时要写明环境版本，修复带来的提升不能算作方法的贡献。
