# 评分说明

你要给 VLM 对机器人仿真回放的回答打分。每个 chunk 文件是一个 JSON 数组，每项含 id、case、truth、model、mode、prompt、answer。逐条阅读 answer，按下面标准打分，**不要调用任何模型 API**，不要看图片，只根据回答文本和下面的真值判断。

## 真值

| case | truth | 真实发生了什么 |
|---|---|---|
| frame_fail | env | 夹爪一直闭合，但框架没有被真正夹住：抓取点处没有可夹的实体（碰撞体缺失），手指穿过把手并拢，框架挂在指尖上，搬运中在爪里下滑、晃动，最终挂不上销钉并掉落。环境问题，不是夹持力或对位问题。 |
| toss_fail | env | 球从一开始就没有被夹住（初始化把球塞进闭合的夹爪），开局 1–2 秒内、抛掷动作之前就掉落或被弹开。环境/初始化问题，不是释放时机或抛掷动作问题。 |
| wipe_fail | env | 海绵从一开始就没有被牢固夹持，按压几次后从夹爪中脱落（海绵关闭了重力，脱落后可能悬浮）。后续动作在空擦。根因在环境/初始化与接触设置，不是擦拭轨迹问题。 |
| push_policy | policy | π₀.₅ 抓住导轨上的滑块后，在向右推的过程中末端沿 z 向上漂移，夹爪从滑块上滑脱，滑块没推到位。环境正常，是策略/观测问题。 |
| peg_policy | policy | π₀.₅ 握着销钉但没能对准插入墙上的方孔（位置或姿态偏差、在孔附近徘徊或插偏）。环境正常，是策略问题。 |
| pull_policy | policy | π₀.₅ 没能成功抓住拉杆把手或没能把拉杆拉到位。环境正常，是策略问题。 |
| frame_ok / toss_ok / wipe_ok | ok | 任务成功完成。 |

## 每条输出一行 JSON

```
{"id": ..., "said_success": "yes|no|unclear", "K": 0|0.5|1|null, "side": "policy|env|mixed|none", "R": 0|0.5|1|null, "halluc": 0|1, "note": "一句话"}
```

- **said_success**：回答是否认为任务完成。P1_describe 往往不明说，按描述推断，推断不了记 unclear。
- **K（关键现象）**，只对 truth 为 env 或 policy 的案例打分，ok 案例记 null：
  - frame_fail：1 = 明确说出框架没有被真正夹住/在夹爪里下滑或晃动/挂在指尖上，同时夹爪是闭合的；0.5 = 提到框架在夹爪中偏移、旋转、偏低、只夹住一边等相关症状但没说它没被夹住；0 = 只描述对位不准、挂不上、掉落。
  - toss_fail：1 = 明确说球在抛掷之前的开始阶段就掉落/没被抓住/被弹开；0.5 = 说球很早（开头 1–2 秒）就离开夹爪但解释为"提前释放/抛出"；0 = 没提到早期脱落。
  - wipe_fail：1 = 明确说海绵从夹爪中脱落/掉落/被顶出；0.5 = 提到海绵位置异常或偏移但没说脱落；0 = 没提到。
  - push_policy：1 = 说出抓住滑块后末端或夹爪向上滑脱/漂移导致丢失滑块；0.5 = 说出夹爪与滑块脱开或推不到位但没说向上漂移；0 = 都没有。
  - peg_policy / pull_policy：1 = 正确描述失败现象（peg：没插进孔、对不准；pull：没抓住把手或没拉起）；0.5 = 部分正确；0 = 错误或没说。
- **side**：回答最终把根本原因归到哪一侧。policy = 策略/动作/控制；env = 仿真环境/资产/物理/初始化/传感器；mixed = 明确说两者都是主因或无法区分；none = 没有给出归因（P1 常见，或判为成功）。
- **R（根因）**：
  - env 案例：1 = 归到环境侧，且指出物体其实没有被真正抓住/抓取点无实体/初始抓取状态有问题这一类根因；0.5 = 归到环境侧但根因不同（如摩擦太小、物理参数不对、海绵悬浮说明重力设置错），或 mixed 且其中包含正确根因；0 = 归到策略侧或 none。
  - policy 案例：1 = 归到策略侧；0.5 = mixed；0 = 归到环境侧。
  - ok 案例：null。
- **halluc**：回答是否描述了按真值不可能发生的明确事件（如无人机坠毁、物体凭空消失、任务成功案例说成失败并编造失败过程），有则 1，note 里写明。拿不准记 0。
- **note**：一句话，说明打分理由，尤其是 K 和 R。

把全部结果写到指定输出文件（JSON Lines，每行一条，条数必须与 chunk 条数一致），最后回复条数与 K、R、side 的简单分布。
